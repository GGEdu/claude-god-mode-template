# Architecture Audit Skill

Usa esta skill cuando necesites auditar la arquitectura de uno o varios proyectos
en el workspace. Cada proyecto recibe un agente `architecture-auditor` independiente
ejecutado en paralelo.

## Prerequisites

- `architecture-auditor` agent available in `.claude/agents/`
- Optionally: `.claude/rules/project/architecture.md` with project-specific rules

## Workflow

### 1. Discover projects

```bash
# List immediate subdirectories of the workspace root (each = one project to audit)
ls -d /path/to/workspace/*/
```

Or use the explicitly provided list from the user.

### 2. Launch agents in parallel

Send a SINGLE message with N Agent tool invocations (one per project). Each agent receives:

```
PROJECT_PATH: /absolute/path/to/<project>
OUTPUT_FILE: /absolute/path/to/<project>/AUDIT_REPORT.md
MODE: standard   # or deep, if requested
```

Wait for ALL agents to respond with `AUDIT_DONE: ...` or `AUDIT_ERROR: ...`.

### 3. Collect reports

After all agents complete, read each `AUDIT_REPORT.md`:

```bash
cat <project>/AUDIT_REPORT.md
```

### 4. Consolidate into AUDIT_SUMMARY.md

Write `AUDIT_SUMMARY.md` in the workspace root with this structure:

```markdown
# Architecture Audit — Summary

Generated: <YYYY-MM-DD>
Projects audited: N
Mode: standard | deep

## Per-project compliance

| Project | Total violations | CRITICAL | HIGH | MEDIUM | Verdict |
|---------|-----------------|----------|------|--------|---------|
| <name>  | N               | N        | N    | N      | PASS/WARN/BLOCK |

## Cross-project patterns

(Pivot: if a violation or extraction candidate appears in multiple projects,
list it ONCE with the list of affected projects — not N times.)

### CRITICAL violations across projects
- `<pattern>` — found in: project-a, project-b
  Fix: <shared recommendation>

### Extraction candidates (cross-project)
| Pattern | Projects | LOC duplicated | Priority |
|---------|----------|----------------|----------|
| `<description>` | N projects | ~N | HIGH |

## Recommended action plan

(Only decisions that need developer input — no implementation code.)

1. [CRITICAL] …
2. [HIGH] …
3. [MEDIUM] …

---
*Generated by architecture-audit skill — claude-god-mode-template*
```

### 5. Do NOT implement

This skill audits only. The user decides what to refactor after reviewing
`AUDIT_SUMMARY.md`. If the user asks for a refactor plan, use the `planner`
agent with `AUDIT_SUMMARY.md` as input.

## Usage examples

**Single project:**
```
/architecture-audit PROJECT_PATH=/path/to/myapp
```

**Multiple projects (orchestrated):**
```
/architecture-audit projects=[/path/to/app-a, /path/to/app-b, /path/to/app-c]
```

**Deep mode:**
```
/architecture-audit MODE=deep
```
